Seven Key Concepts

These concepts summarize the most important ideas behind HTTP and its evolution. Together they explain how web communication is organized, optimized, and protected.

1. Request and Response

HTTP communication follows a client-server pattern. A client sends a request containing a method, target, and headers. The server answers with a status, headers, and often a response body.

2. Statelessness

HTTP is stateless, meaning a request does not automatically depend on previous requests. Applications use cookies, sessions, or tokens when they need to remember users or application state.

3. Methods

Methods describe what the client wants to do. Common examples include GET for retrieving content, POST for submitting data, PUT for creating or replacing a resource, and DELETE for requesting removal.

4. Status Codes

Servers use three-digit status codes to summarize a result. The first digit identifies the category: informational, success, redirection, client error, or server error.

5. Caching

Caching stores reusable responses in browsers, proxies, or CDNs. Proper caching can reduce bandwidth use, server work, and page-loading time.

6. Multiplexing

HTTP/2 introduced streams that allow multiple HTTP exchanges to share one TCP connection. HTTP/3 keeps multiplexed streams but uses QUIC so packet loss on one stream does not have to block unrelated streams.

7. HTTPS, TLS, and QUIC

HTTPS secures HTTP traffic. HTTP/1.1 and HTTP/2 commonly use TLS over TCP, while HTTP/3 uses QUIC, which integrates TLS 1.3 and runs over UDP.

Why These Concepts Matter

Modern HTTP versions change how messages travel across a network, but the core HTTP semantics remain recognizable. Understanding both the semantics and the transport helps explain why HTTP can evolve without changing the basic idea of a client requesting a resource and a server responding.
